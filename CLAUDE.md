# Avalanchego (Flare Fork)

Fork of [ava-labs/avalanchego](https://github.com/ava-labs/avalanchego) with Flare and Songbird network support.
Module: `github.com/ava-labs/avalanchego` | Go 1.26.10 (see `go.mod`/`go.work`; upstream v1.15.2 pins 1.26.10 as well).

**Upstream version:** Pinned to avalanchego **v1.15.2** (branch `flare-merge-1_15_2`, merged on top of the v1.15.1-based `flare-merge-1_15_1`) — this is **not** necessarily the latest upstream release. Newer upstream tags may exist; do not assume features/APIs from later versions are present here.

**The C-Chain is the SAE VM only.** Upstream v1.15.2 deleted the pre-SAE C-Chain VM ("coreth": `graft/coreth/plugin/evm`, `core/blockchain`, `miner`, `eth`, `internal/ethapi`, txpool, atomic VM, …) and stopped wrapping the C-Chain in `vms/transitionvm`; `node.go` registers `vms/saevm/cchain.Factory` directly. What is left under `graft/coreth` (module `github.com/ava-labs/avalanchego/graft/coreth`) is the shared C-Chain plumbing the SAE VM still imports — `params` (+ `extras`), `plugin/evm/customtypes` (header/block extras), `plugin/evm/customheader` (predicate bytes only), `plugin/evm/upgrade/ap3`, `precompile/*` (warp, modules, precompileconfig, precompiletest), `core/extstate`, `core/evm.go` (libevm hooks) and `nativeasset` — plus Flare's additions: the P-chain gateway precompile, `plugin/evm/upgrade/granite` (price floor) and the **legacy `core` package** (`core/state_transition.go` & co.) that the SAE executor uses to replay pre-Helicon Flare/Songbird blocks (see "Coreth specifics"). `graft/evm` (shared EVM/sync code) and `graft/subnet-evm` are unchanged in role. All are wired via `replace` directives in the root `go.mod` plus the `go.work` workspace, and are compiled directly into the `avalanchego` binary. There is no separate `evm` plugin binary and the build does not copy anything into `GOPATH`.

> This is the comprehensive technical **and** upstream-merge guide for the node. The go-flare repo-root `CLAUDE.md` is only a short overview that points here. Paths below are relative to this `avalanchego/` directory.

## Build & Test

```bash
./scripts/build.sh                              # Build node (coreth included; binary at build/avalanchego)
go test $(go list ./... | grep -v /tests/)      # Root-module unit tests (also matches graft pkgs in workspace mode)
cd graft/coreth && go test ./...   # Coreth unit tests
./scripts/localflare.sh                         # 5-node local network (ports 9650-9654)
./scripts/coston2.sh                            # Coston2 node(s)
```

Module hygiene after dependency changes (mirrors `Taskfile.yml` `go-mod-tidy`):

```bash
GOWORK=off go mod tidy                          # repo root
(cd tools/external && GOWORK=off go mod tidy)
(cd graft/evm && GOWORK=off go mod tidy)
(cd graft/coreth && GOWORK=off go mod tidy)
(cd graft/subnet-evm && GOWORK=off go mod tidy)
go work sync
```

**libevm pinning:** the root `go.mod` and all graft modules must require the **same** `github.com/ava-labs/libevm` version (currently `v1.13.15-0.20261019121158-2c4d255e0a63`, as pinned by upstream v1.15.2; it added `Receipt.GasExecuted`/`ExecutionResult.GasExecuted` and `BlockBodyHooks.PostRPCUnmarshal`). The workspace selects the highest requirement; a newer pseudo-version in any module silently downgrades/upgrades everyone and breaks the ava-labs ABI helpers (`PackOutput`, `UnpackInputIntoInterface`, `PackEvent`).

**Protobuf:** generated code lives in `proto/pb`. Regenerate with `scripts/protobuf_codegen.sh` (pins buf 1.70.0, protoc-gen-go v1.36.11, protoc-gen-go-grpc 1.6.2 — check the script, upstream bumps them; install them with `go install …@<version>` first, the script refuses other versions), or `buf generate --path <dir>` from `proto/` with matching plugin versions.

### Genesis Files (`genesis/`)

### Fork Times (`upgrade/upgrade.go`)
- Per-network upgrade schedules (Apricot phases, SongbirdTransition, Banff, Cortina, Durango, Etna, Fortuna, Granite, Helicon, Igloo)
- Every config must set **all** fork fields (the `upgrade` package validates ordering; unscheduled forks use `UnscheduledActivationTime`). Igloo (added upstream in v1.15.2, no content yet) is `UnscheduledActivationTime` everywhere; `Config.LatestTime()` returns it and feeds the network's peer-upgrade tracking and the health API's upgrade check (`node.go`), so keep it updated when upstream adds the next fork
- `ZeroTime` is pinned to UTC so configs survive proto round-trips under deep equality
- `SongbirdTransitionTime` is carried over the plugin VM proto (`proto/vm/vm.proto` field **100**, `vms/rpcchainvm/vm_client.go` + `vm_server.go`); `TestConvertNetworkUpgrades_AllFieldsHandled` guards this. It used to be field 19, which upstream took for `igloo_time` in v1.15.2; the Flare field now sits well above upstream's sequence so future upstream forks (which take the next free number) never collide with it again. Field numbers only matter between a node and its plugin VMs, and the RPC chain VM protocol version is bumped per release anyway

### Staking Parameters (`vms/platformvm/txs/executor/inflation_settings.go`)
- Returns different validator/delegator settings based on network ID and timestamp (`getValidatorRules`/`getDelegatorRules` take a leading `time.Time`)
- Per-network phases are keyed on fork activation (Granite, Helicon) or fixed dates; Coston2's Helicon phase shortens the minimum validator staking duration to 7 days and the minimum delegation duration to 24 hours (Flare, Songbird and Coston have no Helicon phase yet)
- All networks return **0 rewards** (rewards handled via smart contracts); see `vms/platformvm/reward/calculator.go`
- Verification logic in `staker_tx_verification.go`
- **`config.Internal`'s staking fields are not the primary network's limits on the Flare networks.** `config/config.go` `getStakingConfig` honors the staking flags (`--min/max-validator-stake`, `--min-stake-duration`, …) only on local/custom networks; the public networks (`constants.ProductionNetworkIDs` plus Avalanche Mainnet) are locked to `genesis.GetStakingConfig` (since 2026-10-29; before, every Flare network silently ran with the flag defaults = `genesis.LocalParams`, a consensus-relevant node-local setting). The per-network `StakingConfig`s in `genesis/genesis_{flare,costwo,songbird,coston}.go` keep the durations/uptime at the former flag defaults (24h/365d/0.8) because those still reach consensus (permissioned subnet validators in `verifyAddSubnetValidatorTx`, `TransformSubnetTx`, the reward commit/abort vote); the stake-limit fields only mirror the latest inflation phase and are otherwise unused on Flare networks (`genesis/params_flare_test.go` and `config` `TestGetStakingConfigPublicNetworksIgnoreFlags` pin this). Upstream code that reads `backend.Config.{Min,Max}ValidatorStake`, `MinDelegatorStake` or `MinDelegationFee` directly for the primary network must be redirected to `getValidatorRules`/`getCurrentValidatorRules`: the ACP-236 restake in `proposal_tx_executor.go` (`restakeAutoRenewedValidatorOnCommit`) is such a Flare patch — upstream's `safemath.Sub(Config.MaxValidatorStake, weight)` underflowed for every Coston2 auto-renewed validator above the 3M flag default, and since that reward tx is mandatory the P-chain would have stopped at the first renewal; Flare takes the maximum from the rules and clamps weight ≥ max to zero capacity (regression test `reward_validator_flare_test.go`, Costwo network ID). **On every merge grep `vms/platformvm` for `Config\.\(Min\|Max\)ValidatorStake`, `Config\.MinDelegatorStake`, `Config\.MinDelegationFee` outside `inflation_settings.go`.**

### Eth-Style Signatures (`vms/secp256k1fx/fx.go`)
- `VerifyCredentials()` tries two verification methods: standard Avalanche (no prefix) and Ethereum-style (`accounts.TextHash`)
- Allows P-chain transactions signed with standard Ethereum tools
- The two-scheme recovery lives in `vms/secp256k1fx/signing.go` (`SigningHashes`, `RecoverSigner`, `RecoverEthSigner`): `VerifyCredentials` calls it, and the P-chain gateway's `getStakeOwner` reuses it to derive the stake owner's C-chain address — keep them shared on merge
- **C-chain atomic txs (SAE VM; since v1.15.2 the only verifier).** Imports go through `VerifyCredentials` (`vms/saevm/cchain/tx/import.go` calls `Fx.VerifyTransfer`) and inherit the two schemes. Exports identify the signer by EVM address and have their own check, `vms/saevm/cchain/tx/export.go` `verifyCredentials`, which recovers the signer with `SigningHashes.RecoverEthSigner` (plain hash first, then the EIP-191-prefixed hex) — exactly what coreth's deleted `plugin/evm/atomic/vm/tx_semantic_verifier.go` accepted since Banff, ungated because Helicon (the first SAE block) postdates Banff on every network. **Upstream's SAE export verifier only tries the plain hash** — the v1.15.0/v1.15.1 merges shipped it as-is, so eth-signed C-chain exports were rejected on Coston2 from Helicon (2026-11-03) until the fix of 2026-11-05 (rc commit 52812cfe2e, cherry-picked into `flare-merge-1_15_2`). It is an ungated consensus rule among SAE nodes: a node without it drops such a tx in the block-verification rebuild (`hooks.go` `potentialTxs`) and fails the block with `hash mismatch` (`sae/blocks.go`), so every validator must run it before an eth-signed export is submitted. Historical blocks are never re-verified (`sae/blocks.go` `verifyWhenBootstrapping`). On every merge re-check that `export.go` still calls `RecoverEthSigner`; `vms/saevm/cchain/tx/export_flare_test.go` `TestVerifyCredentialsEthSignature` fails against the upstream version

### big.Int Weight Calculations
- Validator weight aggregates use `*big.Int` instead of `uint64` to prevent overflow (Flare has more tokens than Avalanche):
  - `validators.Manager.TotalWeight/SubsetWeight` return `*big.Int`
  - `validators.WarpSet.TotalWeight` is `*big.Int`; the `validatorstate` proto encodes it as `bytes` (regenerate proto after changes)
  - Consumers (benchlist, chains/manager, syncer, tracker, snowman bootstrap) convert via `Float64()`/`IsUint64()` where ratios are needed
- Per-validator weights remain `uint64`

### P-chain gateway precompile (`graft/coreth/precompile/contracts/pchaingateway`, Flare-only, Helicon)

A read-only stateful precompile at `0x0300000000000000000000000000000000000000` (config key `pChainGatewayConfig`) through which contracts **pull** accepted P-chain data during EVM execution: `getPChainHeight()`, `getNativeAssetId()`, `getBlock(height)`, paginated `getTransactions(height, fromIndex, maxTxs, typeFilter, maxInputsPerTx, maxOutputsPerTx)`, `getTransactionInputs(height, txIndex, fromInput, maxInputs)`, `getTransactionOutputs(height, txIndex, fromOutput, maxOutputs)` and the indexer-compatible `getStakeOwner(height, txIndex)`, which returns the attributed owner's P-chain address **and** its C-chain (EVM) address: `(bytes20 pChainOwner, address cChainOwner, bool resolved)`. The C-chain address is recovered from the owner's signature on the transaction with `secp256k1fx.SigningHashes.RecoverSigner` (`vms/secp256k1fx/signing.go`) — the same two-scheme recovery (plain sha256 of the unsigned bytes, then the Ethereum-prefixed hash of its hex encoding) that `VerifyCredentials` itself calls, so the gateway can never diverge from consensus; the reader carries the material as `pchain.Tx.UnsignedBytes` and `pchain.Input.Signatures` (credential *i* belongs to input *i*; a config tx's trailing validator-authority credential is not an input credential; `snow/pchain` keeps its own `SignatureLen` to stay a leaf), `resolved` is true only when the signature recovers to the owner (never false for accepted txs), and the recovery costs a flat `SignatureRecoveryGas` (6 000). Decoded types (1–11): permissionless validator/delegator, auto-renewed add/set-config/reward and the legacy add validator/delegator txs (primary network only), plus import, export, plain-transfer (`BaseTx`) and reward-validator txs. Every decoded tx exposes its produced outputs (BaseTx outputs, then stake or exported outputs, at the P-chain's UTXO indexes; kinds transfer/stake/exported, owner plus stakeable locktime) and its consumed inputs; an import's imported inputs (listed after its P-chain inputs) are flagged `imported` and never resolved — their producing tx lives on the source chain, and a lookup would hit a missing-tx error and invalidate execution. **Every input and output carries its `assetId`** (the P-chain UTXO set holds X-chain assets too, so imports, exports, transfers and the fee side of stakers can move non-native amounts; `getNativeAssetId()` returns the native asset ID from `snow.Context.AVAXAssetID` to compare against), while `weight` and stake outputs are native by consensus — added for review finding PG-04 (2026-09-30); never filter non-native entries, that would break the UTXO indexes. Full ABI, gas schedule, caps and error model in the package `README.md`.

- **Bound.** `vms/saevm/cchain/hooks.go` `BuildBlock` commits `blockCtx.ProposerPChainHeight` — the ProposerVM outer block's own P-chain height, a Flare addition to `snow/engine/snowman/block.Context` (canoto field 2; regenerate with `go generate ./snow/engine/snowman/block/`) filled by `vms/proposervm/block.go` at build (`pChainHeight`) and verify (`childPChainHeight`) and by `vm.go` `SetPreferenceWithContext` (preferred block's height), and carried over the plugin proto as `proposer_p_chain_height` in `BuildBlockRequest`/`BlockVerifyRequest` (`vms/rpcchainvm` `blockContextRequestFields`/`blockContextFromRequest`, `TestBlockContextRequestRoundTrip`). `blockCtx.PChainHeight` stays the ACP-181 epoch height used by warp. The committed value advances with every block (~30 s behind the P-chain via `GetMinimumHeight`) instead of once per 5-minute epoch; observe both with `proposervm.getProposedHeight` / `getCurrentEpoch` or the proposervm "built block" log — into `HeaderExtra.PChainHeight` (`graft/coreth/plugin/evm/customtypes/header_ext.go`, the **last** rlp-optional field — keep it last, nil at genesis and on legacy pre-Helicon blocks, so no existing hash changes). The verifier's rebuild-and-hash-match enforces it (the former coreth-side `customheader.VerifyPChainHeight` guard went away with the coreth VM in v1.15.2; historical blocks are never re-verified). `params/hooks_libevm.go` exposes it to precompiles as `contract.BlockContext.PChainHeight()`; the block JSON shows it as `pChainHeight`.
- **Reader.** `snow/pchain` (leaf: plain types + `Reader`; every read takes a `ByteCharger` that is called with the stored size of the block and of each producing transaction *before* they are parsed, and equally on cache hits, so gas is deterministic; `GetBlock` returns a `BlockReader` handle over the decoded block whose `GetInputs` charges only producing transactions, so one precompile call pays for its block once), implemented by `vms/platformvm/pchainreader` over the Flare state accessors `state.GetBlockBytes`/`state.GetTxBytes` (raw bytes under the P-chain lock, parsing outside it; `LastAcceptedHeight` gallops/bisects the accepted-height index instead of parsing the tip block; input pages are slices of the decoded transaction in its serialized order; decoded-block and owner LRU caches remember the sizes they were charged; owners resolved from the producing tx: BaseTx outputs → returned stake → reward UTXOs → genesis UTXOs; produced outputs are kept as slice references into the parsed tx and converted per requested page by `BlockReader.GetOutputs`, so decode cost and the `ByteGas` calibration are unchanged). The precompile charges `ByteGas` (10 gas/byte, calibrated by `BenchmarkParse*` in `pchainreader`) so cold parses of attacker-sized blocks cannot be bought for a flat fee. `platformvm.VM.NewPChainReader(lock)` implements `pchain.ReaderProvider`; `chains/manager.go` wires it into `snow.Context.PChainReader` for the other chains next to `ValidatorState` (nil for the P-chain itself and plugin VMs). **The manager calls `NewPChainReader` before `Initialize`** (while creating the P-chain), so the reader must stay lazy: `vmStore` dereferences `vm.state` per call and the genesis UTXO list is read on first use — never touch `vm.ctx`/`vm.state` in `NewPChainReader` (`TestNewPChainReaderBeforeInitialize` guards this; the first local-network run panicked on exactly that).
- **Barrier.** `vms/saevm/hook.ExecutionGate` (optional, canonical execution only) is implemented by the cchain hooks: `saexec.Executor.execute` waits until the local P-chain has accepted the committed height (bootstrapping edge), aborting on `Executor.Close`. RPC replays never wait; on a lagging node the precompile calls `InvalidateExecution` instead of reverting (node-local failures must never become catchable reverts).
- **Activation.** `vms/saevm/cchain/genesis.go` adds the `PrecompileUpgrade` keyed on Helicon and activates the account at genesis when Helicon is active there; `hooks.StartExecutingBlock` activates it at the first Helicon block. `TestHistoricalGenesisHashes[Helicon]` (and `[Igloo]`, same hash — Igloo does not change the genesis) changed for that, and so did `TestGenesisHash/local` once `Local`/`LocalFlare` scheduled Helicon at `ZeroTime` (v1.15.1 merge); production genesis hashes did not. Until v1.15.2 coreth's own `parseGenesis` had to schedule the same upgrade because the transition VM let coreth commit the genesis on the local networks (`TestGenesisMatchesCoreth`); the coreth VM, the transition wrapper and that test are gone, the SAE VM is the only writer of the genesis now.
- **Tests.** `vms/platformvm/pchainreader`, `vms/platformvm` `TestPChainReaderOverVM`, `graft/coreth/precompile/contracts/pchaingateway` (exact-gas harness, reverts, invalidation, bech32 attribution, signer recovery in both signing schemes), `customtypes` (`TestHeaderRLP` golden + legacy-compat), `customheader`, `saexec` gate tests, cchain `hooks_pchain_flare_test.go` / `pchaingateway_flare_test.go` (commit, tamper ⇒ hash mismatch, gate, `eth_call`).
- **On merge:** re-check that `saexec.Executor.execute` still calls the gate, `makePrecompile` still fills `pChainHeight`, `precompiletest` keeps `SnowContext`/`PrecompileEnv`, and `header_ext.go` keeps `PChainHeight` as the last optional field (regenerate `gen_header_serializable_*.go` and `precompile/contract/mocks.go` after upstream changes).

### Gossip (`network/p2p/gossip/gossip.go`)
- `Every()` matches upstream: a non-positive frequency clamps to the default period (`defaultRequestPeriod`, 1s). A prior Flare audit fix made it *disable* the loop instead (`return`), but that left the push-gossip queue (`PushGossiper.Add`) growing unbounded with nothing to drain it, so it was reverted to upstream. **Do not re-apply the disable behavior on merge.**

## Coreth (`graft/coreth`) specifics

Since upstream v1.15.2 there is no coreth VM any more: the SAE VM (`vms/saevm/cchain`) runs the whole C-Chain, including the historical pre-Helicon blocks (it executes them as *synchronous* blocks when a node bootstraps from genesis, and replays them for tracing). `graft/coreth` keeps only the packages SAE shares with the old VM (see the top of this file) and, Flare-only, the **legacy `core` package**: `core/state_transition.go` is coreth's `StateTransition`/`TransitionDb` with every Flare mechanism below, `core/state_processor.go` the trimmed `ApplyTransaction`/`applyTransaction` pair over it (block context from libevm's `core.NewEVMBlockContext`; `GasPool` is an alias of libevm's), `core/errors.go` aliases libevm's sentinel errors (coreth's `core/error.go` is gone), `core/main_test.go` registers the libevm extras for the package tests, and the Flare files `daemon.go`, `daemon_call.go`, `state_connector.go`, `governance_settings.go`, `state_transition_params.go` are unchanged. The only consumer is `vms/saevm/saexec.ApplyTransaction` (pre-Helicon branch). Its `ExecutionResult`/receipt carry libevm's `GasExecuted` (always equal to `UsedGas` here, metrics only). Chain-level machinery coreth used to own (block verification, base fee/gas limit schedules incl. the Songbird ones, atomic tx verification, txpool, RPC) now lives in `vms/saevm` and is upstream code (except the export-tx signature check in `vms/saevm/cchain/tx/export.go`, see "Eth-Style Signatures"); the shared EVM/sync/triedb/rpc code lives in the sibling `graft/evm` module.

**Chain IDs** (distinct from the network IDs above; defined in `graft/coreth/params/config.go`): Flare 14, Costwo 114, Songbird 19, Coston 16, LocalFlare 162, Local 4294967295. `vms/saevm/cchain/genesis.go` `berlinBlock`/`londonBlock` pin the mid-chain AP2/AP3 activation heights per chain ID — Songbird London 12 349 716, Coston London 55 188, every other Flare/Songbird network 0 (these came from coreth's deleted `params.SetEthUpgrades`; `genesis_flare_test.go` `TestFlareForkBlocks` pins them). They MUST match the chain config the pre-Helicon node stored, or `verifyAndWriteBlock`'s `CheckCompatible` refuses to start the SAE VM on an existing Songbird/Coston database.

**libevm:** consumed as the upstream-published `github.com/ava-labs/libevm` with **no local fork / no `replace`**. The daemon-call helper that previously required a libevm fork lives in `graft/coreth/core/daemon_call.go` (`DaemonCall` = state snapshot + tracer-disabled `evm.Call`).

**Flare mechanisms** — applied post-EVM-execution in `graft/coreth/core/state_transition.go` (pre-Helicon blocks) via `handleFlareTransitionDbContracts` / `handleSongbirdTransitionDbContracts`, and from Helicon on by `vms/saevm/saexec.ApplyTransactionWithExtras` (fee settlement + daemon call only):
- **Daemon contract (inflation)** at `0x1000000000000000000000000000000000000002` — called each block; returns a mint request (uint256); if valid and ≤ max, tokens are minted to the daemon contract. Max mint: 60M/block on Flare/Costwo/LocalFlare, 50M on Songbird/Coston.
- **Prioritized contracts (fee refund)** — the FTSO contract `0x1000000000000000000000000000000000000003` and the submitter contract get gas fees refunded to the caller. Gas cap: 3,000,000 on Flare/Costwo/LocalFlare; unlimited on Songbird/Coston/Local. Activation times and data prefixes are network-specific (see `graft/coreth/core/daemon.go`).
- **State Connector** (`graft/coreth/core/state_connector.go`) — Merkle attestation protocol; per-network contract addresses, activated at per-chain timestamps.
- **Governance** (`graft/coreth/core/governance_settings.go`) — updates the governance address/timelock and the airdrop/distribution contracts on Flare and Costwo, using the coinbase value as a signal.
- **Fee burn variants** (`graft/coreth/core/state_transition_params.go`) — `stateTransitionVariants` maps the chain ID to (burn address, nominal gas price, isFlare, isSongbird): Flare-family chains burn tx fees to `0x…dEaD`; Songbird-family chains credit the coinbase, which must be `0x0100…00`. The **default** variant (any other chain ID — tests only; every production network's chain ID is registered) credits fees to the **coinbase, matching upstream coreth exactly**. This keeps upstream-generated test fixtures reproducible: the frozen pre-SAE `vms/saevm/cchain/synchronoustest/fixture.json` (recorded from the deleted coreth VM; it can no longer be regenerated) is replayed by the SAE VM with upstream semantics. **Do not change the default variant back to a dEaD burn** — it desynchronizes the fixture from the SAE VM's pre-SAE replay, breaking `TestSynchronousRPCs` (`vms/saevm/cchain/api_test.go`), which replays the fixture's recorded RPC responses. The nominal gas price of prioritised calls is `core.NominalGasPrice` (25 GWei, the former `ap4.MinBaseFee`).

**Accessing extras:** `rulesExtra := params.GetRulesExtra(rules)` (Avalanche/Flare rules) and `configExtra := params.GetExtra(chainConfig)` (chain-config extras). Network classification is on the config: `extras.ChainConfig.IsSongbirdCode()` / `IsFlareFamilyCode()` (they panic without a `SnowCtx`, see `requireSnowCtx`). The former `Rules.IsSongbirdCode`/`AvalancheRules.IsSongbirdTransition` fields were dropped with the v1.15.2 merge (only deleted coreth code read them); the `SongbirdTransitionTimestamp` config field, `IsSongbirdTransition(time)`, fork ordering and `CheckCompatible` entry stay because the stored chain config carries it.

**Gas price floor:** pre-Helicon the Flare-family base-fee floor was `granite.MinGasPrice` (500 GWei) through coreth's ACP-176 parameter set; that machinery (`acp176.Params`, `granite.DefaultParams`, the txpool `SetMinFee` floor) was deleted with the coreth VM. What remains is `graft/coreth/plugin/evm/upgrade/granite.MinGasPrice`, which `vms/saevm/cchain/dynamic.FlareInitialPriceExponent` turns into the ACP-283 minimum-price exponent that SAE seeds at Helicon on Flare-family networks (`hooks.priceExponent`), so the Helicon transition is fee-neutral.

## Key Patterns

- **Network detection**: Use `constants.IsFlareNetworkID(networkID)` / `constants.IsSgbNetworkID(networkID)` to branch on network type.
- **Fork-time gating**: Check timestamps against fork times in `upgrade/upgrade.go` for time-dependent behavior.
- **Flare-family price floor**: `graft/coreth/plugin/evm/upgrade/granite.MinGasPrice` (500 GWei) seeds SAE's ACP-283 minimum price on Flare-family networks (`dynamic.FlareInitialPriceExponent`, selected by `extras.ChainConfig.IsFlareFamilyCode()`).

## Merge Guide for Upstream Updates

This documents merging newer **ava-labs/avalanchego** upstream releases into this fork. The merge is performed in this avalanchego tree; since v1.14.x coreth is part of the avalanchego repository (`graft/coreth`), a single upstream merge brings the avalanchego **and** coreth changes — there is no longer a separate coreth merge.

### Architecture Overview (as of v1.15.2; coreth VM deleted, SAE-only C-Chain)

The coreth remnants (`graft/coreth`, see the top of this file), the shared EVM/sync code (`graft/evm`), and `graft/subnet-evm` are in-tree Go modules wired to the root avalanchego module via `replace` directives in `go.mod` and the `go.work` workspace. They compile directly into the single `avalanchego` binary (no separate `evm` plugin binary, no GOPATH copy). The C-Chain is `vms/saevm/cchain` registered directly in `node.go` (no `transitionvm` wrapper since v1.15.2; the generic `vms/transitionvm` package still exists upstream).

### Merge Process

1. **Create a merge branch:**
   ```bash
   git checkout -b flare-merge-<version>
   ```

2. **Add upstream remote (if not already done):**
   ```bash
   git remote add upstream-ava https://github.com/ava-labs/avalanchego.git
   ```
   Coreth no longer has its own upstream remote — it ships inside avalanchego at `graft/coreth`.

3. **Fetch and merge:**
   ```bash
   git fetch upstream-ava && git merge v<version>
   ```
   This single merge also brings the `graft/coreth`, `graft/evm` and `graft/subnet-evm` changes.

4. **Resolve conflicts following the guidelines below**

5. **Run module hygiene:** `GOWORK=off go mod tidy` in each module (`.`, `graft/evm`, `graft/coreth`, `graft/subnet-evm`), then `go work sync`

6. **Build and test** (`go build ./...` and `go vet ./...` in `.`, `graft/coreth`, `graft/evm`, `graft/subnet-evm`; regenerate `proto/pb/vm/vm.pb.go` when `vm.proto` changed)

### Known Issues

- **Network binding tests:** Tests requiring `listen tcp 127.0.0.1:0` will fail in sandboxed environments. This is not a code issue.

- **Restarting a local network after the SAE transition:** `state-sync-enabled` defaults to `true` for the C-chain after Helicon (upstream v1.15.0), but `statesync.Handler.GetLastStateSummary` serves summaries only at `commit-interval` (4096) heights and never for synchronous (pre-SAE) blocks such as the localflare genesis, and the state syncer restarts forever when no sampled beacon can answer ("didn't receive enough frontiers"). A restarted localflare then never leaves bootstrapping (every chain RPC returns `503 API call rejected because chain is not done bootstrapping`, the P-chain logs "bootstrapping skipped" every 10 s, the C-chain "starting state sync" every 2 s). `configs/chains/C/config.json` (used only by `scripts/localflare.sh`) therefore sets `"state-sync-enabled": false`; keep it on merge. A fresh `--clean` start is unaffected (the first block is still the legacy VM's).

- **`TestCheckCompatible`:** May fail due to error message changes. Update test expectations if the logic is correct.

- **`vms/saevm/cmputils/types.go` vet warning** (`func passes lock by value: sync/atomic.Pointer`): upstream code, identical to v1.15.2; `go vet` prints it but it is not a Flare issue.
